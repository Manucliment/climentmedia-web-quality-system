# Traps §77–§81

Part 5. Index and families: [`../traps.md`](../traps.md).

All four were found on the same day, porting this system out of the private tree it grew in.
Three of them are the same shape: **a guard that kept working, kept printing, and had stopped
looking.** None of them failed. That is why they are here.

---

## §77 · A sweep for unwired test batteries went mute when the batteries were renamed

`run-all.sh` carries a census: any battery directory that exists but is not wired into the
runner gets named out loud. It was written after two batteries — one of 898 files — sat
unrun for weeks, because *writing a battery and wiring it in are two gestures, and only the
first leaves a visible trace.*

The census globbed `*-pruebas` and `*autoprueba*.pl`. Porting the tree renamed every
battery directory to `*-tests` and the self-test to `*selftest*.pl`. Measured afterwards:

| glob | matches |
|---|---|
| `*-pruebas` | **0** |
| `*autoprueba*.pl` | **0** |
| `*-tests` | 13 |
| `*selftest*.pl` | 1 |

The census kept running and kept printing nothing. **Printing nothing is exactly what it
prints when everything is wired in.** It had zero subjects and reported zero findings, and
those two are indistinguishable on the way out.

It is the defect the check was written to catch, committed against the check itself.

**Caught by:** the check now counts what it looked at, and **a census that found NOTHING TO
LOOK AT says so and goes red.** Zero findings over thirteen directories is good news; zero
findings over zero directories is a blind instrument.

> **Any sweep that reports by exception must publish its denominator.** "No problems found"
> and "I found nothing to examine" have to be different sentences, or the second one will
> eventually be read as the first.

**The cheap signal:** a guard that has never once named anything, in a tree that has been
renamed since it was written.

## §78 · A discovery step conditional on an ABSENCE, disarmed by adding one file

The documentation gate lives in `gates/` with the programs, while the prose lives in
`blueprint/`, `paths/`, `docs/` and `checklists/`. To bridge that, it walks the sibling
directories — but only under this condition:

```perl
if (!@DOCS && @PROGS) {     # only if THIS directory has no documents of its own
```

Then `gates/README.md` was written. One file. `@DOCS` became non-empty, the sibling walk
never ran, and:

- D1 went from **35 documents** to **1**.
- D4 stopped finding the trap log at all — **76 traps to none**.

And it did not go red. D4 degrades to a **warning** when it finds no trap file, because the
same gate is run against site repositories that legitimately have none. So `run-all.sh`
went on printing `PASA` over a documentation gate that was reading one file out of
thirty-six.

**Caught by:** it now walks whenever the parent **looks like this repository's root** — it
holds at least two of the prose directories — and merges. D1 reports the document count.

> **The first fix was to make the walk unconditional, and that broke two cases of this
> gate's own battery within a minute.** The battery builds a fixture tree, and `..` of a
> fixture tree is a scratch directory: the gate swept in two unrelated documents and
> reported twenty findings that were nobody's defect. Removing a bad condition is not the
> same as needing no condition. The one that works is a **positive structural fact** about
> where it is, not a statement about what is absent.

> **A step armed by an absence is disarmed by anything at all.** Nobody adding a README
> thinks they are touching discovery. The gate was not fooled by a clever case; it was
> fooled by a perfectly ordinary one.

**The cheap signal:** a count that anybody can read — *35 documents* — printed next to the
verdict. The failure was visible in `1 documentos` the moment it happened, but only because
the number was there to compare against. **Print what you looked at, not just what you
found.**

## §79 · The hook and the door are coupled by a filename, and renaming the door disarmed the exemption

The deploy hook denies anything that writes into a document root. It has to let the door
itself through, and it recognises the door the only way it can — by name:

```sh
printf '%s' "$payload" | grep -q 'deploy.sh' && exit 0
```

Renaming the door in this repository left the installed hook exempting the **old** name. It
started denying the door. The battery went from 25 OK to 21, and the four reds were the
door refusing to open.

Two things make this worth writing down rather than shrugging at:

1. **It failed towards BLOCKING**, which is the cheap direction. A guard that only ever errs
   by getting in the way is the error you can afford; the same coupling failing the other
   way would have let deploys through silently.
2. **The coupling is not a mistake to be removed.** Recognising the door by name is the
   whole point — the hook cannot see inside a script to know where it uploads. The defect is
   not the coupling, it is that the coupling was **written in one file and depended on
   another**, with nothing asserting the pair.

**Caught by:** `gates/receipt-tests/tests-hook.sh`, two cases, and it takes both to mean
anything: the current door name is exempt, **and** a different deploy-ish name is not.

> A first attempt at the negative case used a filename the hook does not recognise as a
> deploy script at all. It passed — through a completely different exit, for a reason with
> nothing to do with the exemption. **A case that goes green by accident is worse than no
> case**, because it also reports coverage.

**The cheap signal:** the guard denying something it is supposed to permit, in the same week
somebody renamed a file.

## §80 · Porting a construct by copying the line `grep` showed me

The hook's whole purpose is one JSON verdict on stdout. Reading the original with `grep`
returned the JSON line, so that line got copied into the port. What `grep` did **not** show
was the line above it:

```sh
cat <<'JSON'
```

Without the heredoc, the shell reads that JSON as a command **word**, brace-expands it on its
commas, and tries to execute it. The hook exited 127 and denied nothing.

Every single case that was supposed to block, passed — **11 of 11**. That is the signature
from the front of this log: *if the sweep says everything is broken at once, the broken thing
is the sweep.* Applied here it read: if the guard permits everything, the guard is not
running.

**The failure direction is the bad one.** A hook that dies open looks identical to a hook
with nothing to complain about. Installed without a battery, it would have protected nothing
and reported nothing, indefinitely.

**Caught by:** `tests-hook.sh` — but only because it has positive cases. A battery of
negatives alone would have been **fully green** against a hook that had stopped working.

> **`grep` returns lines. Code is not made of lines.** A construct that spans lines —
> heredoc, block, opening brace, `while` guard — is invisible to the tool most likely to be
> used to find it. When lifting code, open the file at that point and read around it.

**The cheap signal:** run the ported thing once against the case it exists to catch, before
believing any of its other output.

## §81 · The census counted directories, so a whole battery hid inside a wired one

§77 fixed the sweep that finds batteries nobody runs. It still had the other half of the same
blind spot: it accounted for **directories**.

`grep` for a directory name matches as soon as **any one** script inside it is wired. So a
battery living in an already-wired directory is invisible to the check written to find exactly
that. Two were:

| Battery | Lives in | Directory wired? |
|---|---|---|
| `receipt-tests/tests.sh` | `receipt-tests/` | yes — five *other* scripts of it are |
| `structure-gate-tests/battery-layout.sh` | `structure-gate-tests/` | yes — `battery.sh` is |

The first one had never been run by any runner. The day it finally was:

```
  62 PASA · 6 FALLA
```

**Six red cases nobody had ever seen.** All six had one cause, and it was not a broken gate:
the fixture declared that the structure lens had **looked at 2 URLs** while every one of its
checks was `NOT VERIFIED`. The receipt gate refused it, correctly — a lens that ran and
measured nothing is not a pass. The fixture had quietly stopped matching the code it tests,
and nothing could say so, because nothing ran it.

**It is upstream's state too, not something the port introduced** — measured by running the
original: **62 · 6, identical.** Worth checking before claiming a defect is yours or theirs.

**Caught by:** the census now enumerates **entry scripts**, matched literally, and the runner
names the exact file. Verified in both directions: unwire one and it is named; wire it and the
line disappears.

> **Pick the unit that can be run.** A directory is not a thing you execute, so it cannot be
> the thing you account for. Any coverage check that counts containers instead of runnables
> will eventually report a container as covered while something inside it does nothing.

**The cheap signal:** a battery directory holding more entry scripts than the runner names.
