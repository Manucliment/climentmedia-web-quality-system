## §41 · The process was written end to end and its gates had never been seen to fail

**Caught by:** the coverage counter, comparing **checks the program emits** against **checks with
a case in its battery.** It is the only thing that looks at this, and it blocks nothing: it is a
number you have to go and read.

Path 1 has **14 steps and all 14 declare their gate.** On paper, the process of building a site
was complete from A to Z. Measured, the truth was different:

| | |
|---|---|
| Steps that rest on the spec auditor | **7 of 14** |
| Checks in that program with a case | **5 of 25 (20%)** |

And the 20 without a case **were not the exotic ones**: they were exactly the ones on the build
path — intake, skeleton, anatomy, linking, inventory, images, measurement, forms, pages.

> **Two skeleton checks are the threshold the document itself names** for deciding whether to
> clone a skeleton — and they had never been seen to fail. The skeleton is cloned from the one
> repo missing a `404.html`. That gate exists so the hole does not travel in every copy, and
> nobody had checked it could see it.

**A process written end to end whose gates have never been seen RED is not a process: it is an
index.**

### The hole that surfaced while writing the cases

The "invented" block **only runs in greenfield.** The reason written in the gate is sound: in a
migration, the inventory against their code is done elsewhere and is not repeated.

**But two of those three checks — filler text live, and schema claiming something the site does
not have — are not inventory: they are defects of what is published, and they happen in a
migration too.** And the proof is in-house: a search-action schema with no search function was a
defect on a site that is **a MIGRATION**.

**The check that would have caught it is switched off in exactly the mode where it happened**, and
what hid that was the migration fixing it by accident.

It has not been changed: moving which blocks run per mode touches all five repos. **It is pinned
with a case** that asserts today's behaviour, so whoever changes it sees red and knows they are
changing it.

### Three things learned writing the cases, which a spec reader will thank you for

1. **A boolean `true` is not enough** for "we do not publish an address": the gate requires a value
   with text, so you have to write the **reason.** That is not pedantry: *"not published: we work
   at the customer's premises"* is understandable in six months; `true` is not.
2. **The type is only honoured in one collection.** Elsewhere it is derived. Declaring it there
   does nothing, and the symptom is that the anatomy gets measured against a different type.
3. **The intake check accepts three keys or a handler with a mailbox.** It is the kind of value
   everybody writes wherever it seems right, which is why the gate looks in several places.

### The result

| | Before | After |
|---|---|---|
| the spec auditor | 5 of 25 (**20%**) | **25 of 25 (100%)** |
| total instrument coverage | 52% | **68%** |
| battery | 458 cases | **500, 0 red** |

## §42 · Writing the case found two gates that could not see what they claim to measure

**Caught by:** the cases themselves. Both defects had been there since the checks were written, and
**no run over the five live sites would have exposed them**: one stayed silent and the other
over-accused.

### 1 · A landmark check counted the `<main>` inside a comment

The good fixture had **one** `<main>`… and a comment explaining the defect:

```html
<!-- TWO <main>: the skip-to-content link stops being deterministic -->
```

The gate counted **that one too** and said there were two. A correct page, red, for documenting the
defect it avoids.

> Same family as an integrity check flagging itself for mojibake while scanning the document that
> documents mojibake: **a sweep that does not distinguish code from prose accuses the documentation
> of being the defect.**

### 2 · A honeypot check could not see the only honeypot we have in production

The detector looked for `honeypot|hp_|_gotcha|bot-field`. **The honeypot on one live site is called
`website`** — the classic name, chosen precisely because it looks like a normal field.

Result: the check **never fired** on the only form in the estate that has a honeypot. And that
honeypot **was visible on screen**, silently discarding the enquiries of anybody who filled it in.

The three classic names were added, and the check was **deliberately aligned with the browser-side
forms gate**: two gates looking at the same thing with two different lists end up disagreeing, and
then one of them is lying and nobody knows which.

### What to take from it

Both came out of **writing the case, not running the gate.** A check that has never been exercised
with an input built on purpose has only been tested against what we already had — and what we
already had included neither a comment naming `<main>` nor a honeypot called `website`.

**Covering a check is not just raising a number: it is the first time anybody asks it something it
did not know how to answer.**

## §43 · An HTML comment could PASS a compliance check

**Caught by:** the master gate's battery, the case *"consent AFTER the container, FAILS"*. Before
that, nobody, and the defect had been there since the check was written.

It is the **third** of the same family in one day — and the only one of the three that does damage
towards the dangerous side.

### What was happening

The check verifies **order**: the consent default with everything denied has to come **before** the
tag container loads. The other way round, the container sets cookies before anybody accepts
anything, the banner looks exactly as good, and the site is in breach.

The check compares two positions inside the HTML, and **it did not strip comments.** The red
fixture carried, before the container:

```html
<!-- FIXTURE: container FIRST and the consent default AFTER. -->
```

The gate read that *"consent default"* as the real declaration, placed it before the container, and
gave **PASS** to a page that loads the container without consent.

### Why it is worse than a false positive

| | a false-positive check | **this one** |
|---|---|---|
| Effect | accuses a correct page | **passes one that is in breach** |
| Who notices | whoever fixes it, immediately | nobody |
| Who pays | us, for a while | **the visitor**, with cookies they did not accept |

A false positive discovers itself, because it is annoying. **A false negative annoys nobody: it
comes out green.**

And the trigger is especially perverse: **the better you document the check, the easier it is for it
to pass itself.** A template with a comment explaining why the order matters would have passed the
check forever.

### The rule

**Every sweep that measures POSITIONS or COUNTS tags strips comments first.** It is not defensive:
comments are the one place in HTML where the vocabulary of the defect you are looking for appears on
purpose.

### The full sweep, done the same day

It was not eyeballed: **a CORRECT page was fabricated whose comments name the vocabulary of every
check**, and we looked at which ones changed verdict. Six fell:

| Check | What the comment said | Effect |
|---|---|---|
| landmarks | "never two `<main>`" | false positive |
| headings | "the second `<h1>`" | false positive |
| SVG naming | "an `<svg>` needs aria-hidden" | false positive |
| heading order | "an `<h2>` after an `<h4>` is a skip" | false positive |
| render-blocking | "a script without defer blocks" | false positive: it demanded a commented-out resource |
| **consent order** | "the container goes AFTER the consent default" | **false NEGATIVE** |

**And the three browser gates are immune**, verified: they read the DOM with selectors, and the DOM
does not expose comments to a selector.

### How it was fixed, and why that way

Not check by check: **at the point where each lens takes the page body** — nine entry points. The
list of checks grows every week; the list of entry points has not moved in a month.

> And a detail that cost an iteration: in the consent check the "skip unless there is a container"
> filter ran BEFORE stripping comments, so a comment naming a container made the check **enter** a
> page that has none — and then it failed for "no consent". **Stripping comments late does not fix
> it: it moves the error.**

The fixture stays as a permanent case: **a correct page that documents defects cannot be accused of
having them.**

## §44 · Three tables that promised to be twins, and seven of twelve types disagreed

**Caught by:** the anatomy battery (8 cases) and the anatomy gate, which runs inside the runner.
Before that, nobody.

The anatomy table — which sections each page type carries — was written **three times**: in two Perl
gates and one browser gate. And one of them carried this note, written in good faith:

> *"Same table as the master gate. It is duplicated ON PURPOSE and with this warning: if the
> document changes, you change BOTH."*

Measured, **7 of the 12 types disagreed** — and the two that promised to be twins were exactly the
ones that had drifted from the canonical document:

| type | the document asks for | what was written |
|---|---|---|
| detail page | + proof, objections, siblings | the Perl gates asked only for hero, offer, closing |
| hub | + qualification | missing. It is "how to choose between the children": what distinguishes a hub from a menu |
| guide, comparison | + objections | missing |
| pricing | + proof, process | missing |
| contact | proof is required; map is conditional | it demanded the map and did not ask for proof |
| thanks | + closing | missing |

### The worst part was not the disagreement

The browser gate had no key for one type: it called it something else. And that other name **is not
emitted by a single page on any of the five sites** (census: 12 distinct values, none of them that
one). So on the 8 real pages the lookup was `undefined`, the missing-roles list came out empty and
**the check looked at nothing.** Green over nothing, for as long as it had been written.

### The fix, and why the copy still exists

One single table: `gates/anatomy.tsv`. The two Perl gates **read it** and **die** if it is missing —
no fallback table: a default is how you diverge silently again. The browser gate cannot read it,
because it is evaluated inside the browser; it carries a **generated** copy between markers, and the
anatomy gate compares them character by character.

**A copy is only safe if something goes red when it drifts.** Four controls, all four seen red before
being accepted:

- **A** · count the required markers per section of the markdown document and compare against what
  the table declares. **This is the independent anchor**: it does not come from the table, so it
  detects the document changing.
- **B** · no Perl gate may declare the table by hand again; it has to call the loader.
- **C** · the embedded block in the browser gate against the table.
- **D** · the table exists and has types in it.

### What it found the moment it was wired

**21 pages across two live sites** that had been passing a check that was not being performed. Two
other sites were clean.

And the test site — 12 pages built by reading **the document**, not the gates — satisfies the
corrected table **on all twelve.** **The pages were fine; the instruments were not.**

## §45 · The form template passed the exam it came to set

**Caught by:** the spec auditor's battery, the cases *"with the TEMPLATE's address, FAILS"* and *"an
example mailbox in the spec does not get through either."* Before that, the battery **pinned** the
defect instead of catching it.

The intake check exists for a specific case: a form spent months submitting to a cancelled CRM,
answering 200, and nobody noticed.

The reusable form handler is the file you copy to fix exactly that. And it shipped with
`MAIL_TO = contact@example.tld`: an address **shaped like an address**. The check looked for "an
address, not just an at sign" — it had already been cured of a PHP error-suppressor sneaking through
— but not for the address being fake. **Copying the template and not touching it turned the check
green.** And the test battery used an example address to demonstrate that it passed: the instrument
was **pinning** the hole.

**The fix goes through both sides**, because either one alone is just walked around:

1. The check rejects filler addresses (`example`, `domain`, `.tld`, `.invalid`, `.test`…) and says so
   with a different title: *"the lead destination is the TEMPLATE's, untouched."*
2. The handler **refuses to work** unconfigured: a 500 and a message saying which constant is
   missing. **Answering 200 with no mailbox is the entire defect.**

> And the first thing running it found — not a syntax check, **running it** — was an undefined-key
> warning that would have ended up in a client's error log.

The battery has 6 cases, **two of them controls that the battery can go red**: a file with broken
syntax has to fall, and the template without its guard has to stop warning. Without those two,
"passes" would mean nothing.

## §46 · The system required sealing the CSS and its own auditor failed it

**Caught by:** nobody — the site auditor has no test battery, and there are three copies in three
repos. Verified by hand in both directions; **declared debt**, not something watched automatically.

§15 requires serving CSS and JS with a version query: without it, the browser serves the old
stylesheet and a computed style lies.

One auditor check resolved the **whole** `href` against disk. With `styles.css?v=20260818-1` it
looked for a file called that, did not find it, and marked FAIL. On the test site: **12 FAILs, all 12
false.**

And the reason it had never been seen is the uncomfortable one: **not one of the five repos seals its
CSS.** The rule and the auditor had gone months without meeting.

Fixed in all three copies by stripping query and fragment before resolving. Verified in both
directions: green with a sealed sheet that exists, **red** with a sealed sheet that does not, and red
with no sheet.

> And the underlying thing stays on the record: **the site auditor has no single source either** —
> three copies in three repos, which is the same disease as §44.

## §47 · "No block taller than one screen" applied to a list forbids having more than two ideas

**Caught by:** the density battery (24 cases, measured on the server): the four walls that must fall,
the good list that must pass, and the 19 moulds.

The 19 moulds were measured **on the server** at 390×844 (`innerWidth` 390 and matching on all 19):
**ten exceeded one screen** with their own example content.

**None of their units did.** One mould is 3 rows of 0.74 · 0.69 · 0.66 screens. What overflowed was
**always the sum, never the piece.**

So the rule as written actually said *"no section may have more than two ideas"* — and that collides
head-on with the anatomy document, which requires an offer block of **3 to 6 items in ONE section.**
Two canonical documents demanding incompatible things: **using the repertoire the system requires
you to use failed the gate the same system requires you to pass.** And the easy way out — remove the
primitive — returns the page to the original defect.

### The fix

Measure the **UNIT**: the piece that repeats **and is structured.** Eight consecutive paragraphs also
repeat and are **not** units — a paragraph never is — so the wall of prose, which is what this gate
exists to catch, still falls. And the container has its own ceiling, 3 screens, anchored to the one
site that passed first time and whose **whole page** is 3.2.

Four negative controls, all four seen red: a wall of 6 paragraphs · the same wall with a link and
bold inside each paragraph, in case "it has two children" got through · a single unit of 1,628 px ·
twelve small units summing to 5 screens.

**Measured effect across the 5 live sites at 390: ZERO verdicts change.** On one, 2 accusations
disappear (they were lists) and the real one remains — 2.7 screens with no call to action; on
another, **a new accusation appears** from the container ceiling. It does not loosen: it sharpens.

## §48 · CSS reads attributes too

**Caught by:** the spec auditor's battery, three cases including *"but one that neither the CSS nor
the JS reads still falls."*

The measurement check cross-references the data attributes the generator **writes** against the ones
the runtime **reads**, and it only looked at the JavaScript. One mould emits an attribute whose
mobile mechanism is `content: attr(...)` **in the CSS**: the attribute has a reader, and in fact it
is the one that makes the table usable on a phone.

It now accepts `attr(data-x)` and the `[data-x]` selector as readers, and **says which** in the pass
line. Verified that an attribute nobody reads still falls.

## §49 · A doubled backslash vanishes in transit, and the regex goes mute

**Caught by:** nobody — it is a method trap. The only thing that avoids it is re-reading the line you
just wrote, from the file.

Rewriting a line of a gate from a helper script, a `\S` written as a doubled backslash arrived in the
file as **`/S/`**. A syntax check said **OK**: it is a perfectly valid regex matching the letter S. It
would have made the intake check accept a destination only if it contained an "S".

It was caught by an "unrecognised escape" warning and, above all, **by re-reading the written line
from the file.** The rule, which is the usual one in another shape: it is not enough that the program
doing the writing says it made a substitution — you have to **look at what is there.**

The shape that does work when you need a literal backslash: build it in execution
(`my $B = chr(92);`) and concatenate. No doubled backslashes anywhere.

## §50 · The layout gate did not look at the declared type: it audited against the wrong anatomy

**Caught by:** nothing automatic — that gate has no battery wired into the runner. Verified by hand
live and with two fixtures.

The master gate has a case called *"declared beats the path"*: if the page carries a type attribute,
that value wins over anything guessed from the URL. **The layout gate did not do that.** Its type
inference looked only at the path, the title and the heading, and the attribute did not appear in the
file once.

Measured live on a page that declares its type:

| | type | what it demanded |
|---|---|---|
| before | inferred from the path | two roles **that this type does not carry** |
| now | the declared one | two roles **that are genuinely missing** |

Two errors in the same line: it accused of two false things and **could not see the real one.** And it
was one of the silent ones: the report said "inferred from the path" on a line nobody reads.

**And a declared type that is not in the table no longer passes silently**: before, the lookup came out
undefined, the missing-roles list stayed empty and the check went green without looking at anything.
Now it emits a failure saying *"NO anatomy was checked."* Without that, anybody can dodge an
inconvenient anatomy by writing a new word.

## §51 · 727 FAIL runs over real sites, and not one says what failed

**Caught by:** the history gate, wired into the runner. Verified in both directions: green over the
real history, and **red** when a nameless FAIL line is injected.

The receipt walked the checks and did this:

```perl
if ($c->{state} eq 'FAIL') { $lens{$l} = 'FAIL'; $nfail{$l}++ }
if ($c->{state} eq 'NV')   { push @nv, $c->{id} }
```

For **NOT VERIFIED** it kept the id. For **FAIL**, a counter. **The name of the accuser was thrown
away.**

Measured over the history file: **727 lines with a FAIL verdict, zero with an id.**

### Why it is the defect that holds up all the others

It is the reason nobody could ever notice that most accusations were false: **the record does not keep
the accuser.** With no name you cannot know which gate earns its place and which one just makes noise,
so the only possible operation on the instrument was **adding.** In 50 traps written, not one check had
been retired.

Fixed in the three places that needed it — and **I nearly left it with no effect**: the master gate
built one list and not the others, so the receipt received an empty list and everything stayed the same
with three files touched. I caught it by looking at who calls whom, not by running it.

> **The header gets migrated, not left lying.** Adding a column to an append-only file leaves the first
> line with 7 names for rows of 8 fields: a reader by index does not notice and a reader by name goes
> quietly wrong. You rewrite it once. The 1,257 old rows keep 7 fields **on purpose** — you do not
> invent what was not recorded, and that width difference is exactly what the gate uses to know which
> line is from which era, without depending on a hand-written date.

## §52 · The coverage counter published 100% of a rule it had never looked at

**Caught by:** the coverage counter itself, which now prints its SCOPE on every run. The quote bug is
caught by nothing automatic: what gave it away was **the number moving** when it was fixed (10 of 10 →
10 of 11).

Two defects in the same program, and both towards the reassuring side.

**The first, a quotation mark.** One rule was declared with **double** quotes. The extractor only read
single ones. Result: that rule did not exist for the counter, the denominator came out 10 instead of
11, and the program published **"10 of 10 — 100%"** over a rule it had not looked at. That rule has no
test case and never has had one.

It is §14 again: **a control anchored to its own grep believes itself.**

**The second, a denominator that does not say what it is of.** The pair list has **4** entries and the
folder has **20** programs. The percentage reads as *the instrument's coverage* and it is one fifth's.
**A high number over a small slice reassures more than it informs** — and that is how I ended up
quoting a figure for an instrument whose bulk has nothing to fail with.

The scope is now printed **always**, not behind a flag:

```
SCOPE: measures 4 programs of 20. NOT measured: <names>
That % is of the 4 measured, NOT of the whole instrument.
```

**What is not seen does not get corrected. And a percentage with no declared denominator is an opinion
wearing the face of a measurement.**

## §53 · A battery written and never plugged in spends months pointing at a real defect, in a vacuum

**Caught by:** the runner — the inverse control to the one it already had. The old one catches a battery
that **disappears** from the run; this one catches the one that **never entered.**

Two test suites existed without being in the battery list. Nobody ran them, and their absence was
invisible: **writing a battery and wiring it are two gestures, and only the first leaves a visible
trace.** A directory full of tests looks like finished work.

Running one by hand produced what it had been saying to itself:

> *"The compliance matrix declares a check as home-page-only and it is NO LONGER: remove it, or the
> matrix will keep downgrading a compliance that is now site-wide."*

True, verified. The matrix had been downgrading two real compliances, and the test that said so was read
by nobody.

> **Two were removed and NOT the other four.** The probe did not observe the other four firing outside
> the home page, and removing them "while we are here" would be inventing evidence. **You remove what
> you measured.**

And wiring them meant giving them a contract, because neither had one: one printed fourteen pretty lines
and **exited 0 whatever happened**; the other printed a count in a format the runner cannot read, which
would have counted as zero cases — **a zero wearing a pass.**

## §54 · I wrote §43 in the morning and reintroduced it in the afternoon, in the same file

**Caught by:** the spec auditor's battery, the cases *"a mailbox that only lives in a COMMENT does not
count"* and *"and an https:// URL is not split by the comment stripper."*

§43 says, in those words, that **a comment could PASS a compliance check.** That same day, hours later,
the spec auditor was doing this:

```php
// TODO: when the client answers, put info@client.example here
const MAIL_TO = 'FILLME@example.tld';
```

→ the intake check **GREEN.** The check that exists because of a dead CRM was approving a site whose form
goes nowhere, and approving it **through its own documentation.**

The master gate strips comments in **20** places. The spec auditor, in **zero**, with 15 file reads.
Nobody had looked because §43 was written about a different program.

**The lesson, and it is the whole day's lesson: knowing the trap does not avoid it.** I knew it, I had
just written it, and I repeated it. **The only thing that avoids it is a mechanism.**

> And the comment stripper cannot be blunt: a naive `s{//.*}{}g` takes the `//` out of `https://`. So
> `//` only counts as a comment if it starts the line or follows a space, and **never** if a colon
> precedes it; and `#` only at the start of a line, so the hex colours in CSS survive. There is a case
> for each.

## §55 · An exit code read through a pipe is the pipe's

**Caught by:** nobody — a method trap.

It happened to me **three times in one day**, always the same:

```bash
perl program.pl | tail -6; echo "rc=$?"     # this is tail's rc, not the program's
```

All three times it made me believe the opposite of what was happening: I accepted that one gate failed and
returned success (it returned 1, correctly), and that another flagged nothing (it flagged, and exited 1).

A false positive about the instrument costs the same as one about a site: **you fix what is not broken.**

→ **The exit code is measured without a pipe:**

```bash
perl program.pl > /tmp/x.txt 2>&1; echo "rc=$?"
```

## §56 · The three browser gates depended on a file that existed nowhere in our tree

**Caught by:** the door's browser step and the density battery, which **push** it on every run. Verified by
deleting it from the server: the battery goes from **24 of 24 to 0 of 24**, and the next run restores it and
returns to 24.

The runner for the three gates evaluated inside the browser existed only on the server: unversioned, uncopied
and unwatched.

And the door's step did this:

```sh
elif ! ssh "$HOST" 'test -f ~/webtools/run-gate.js'; then
  echo "  browser: ... NOT MEASURED."
```

**It checked whether it was there** and, if not, dropped the three gates to NOT MEASURED — in the same step
that already pushes the gates *"because two copies diverge on day one."* The runner was the exception to its
own rule. A single delete on the server switched off half the door, the deploy carried on, and the hole was
recorded so formally that it caught nobody's attention.

The documentation gate did not catch it because it only checks paths under its own references directory, and
the citation in a comment was bare: *"it runs with `run-gate.js` on the server."* **A citation without a path
is invisible to the documentation gate.**

**The general shape:** if a program of ours has to be on another machine for a gate to work, **it gets pushed,
not assumed.** And if it is cited in a comment, it is cited with its path.

## §57 · In `grep`, a `.` does not match an accented letter

**Caught by:** nobody — a method trap, sibling of §55.

Re-checking eight fixed steps, three came out **"not fixed"** and all three were fixed. The pattern used `.`
to match an accented capital: in UTF-8 that character is **two bytes**, and `.` matches one.

And the third was worse for another reason: I grepped for a phrase to confirm it was no longer cited, and got
1 — it was **my own text explaining that it is no longer cited.**

All three failures go in the same direction, the demoralising one: **they make you believe the fix was not
applied when it was.** And the natural reaction is to apply it again, which in a file means duplicating the
patch.

→ **ASCII anchors for verifying accented text**, and if the pattern could appear in the explanation of the
fix, **anchor it to the exact shape of the instruction**, not to the loose phrase. It is the "a sweep with an
invented pattern measures my hypothesis, not the fact" rule applied to checking my own work.

## §58 · The fix for §47 brought its own invented threshold, and produced five new false accusations

**Caught by:** the same 24 density cases. And what gave it away was not the battery: it was **measuring the
test site and opening the accused block.**

In the morning, §47 changed the density rule from "the block" to "the unit", and removed 8 false accusations
across the 19 moulds. In the afternoon, measuring the test site with that rule, **five new false accusations**
appeared.

The cause: to find the unit, the detector descended into the tallest child **only if it exceeded 55% of the
block's height.** A 55% I invented. A completely normal section — heading + subtitle + intro paragraph + a list
of 4 cards + call to action — leaves the list at **52%.** By three points it gave up and declared "the whole
block is the unit": **1.3 screens over a section whose tallest piece is 136 px.**

### The rule that replaces it, and why it is better and not merely different

The reason for the threshold was always *"if it does not fit in one glance, it does not get read: it gets
skimmed."* So what has to be measured is not the size of the piece: it is **how far you travel without finding
somewhere to stop.** A stop is a heading, a list item, an image, a table row, a button, an accordion summary
**and a form field with its label** — a form is not skimmed, it is filled in, and it is traversed by its
labels just as a list is by its items. **A paragraph is not a stop.** That is the whole rule, and it has no
number I chose.

### Compared over the same estate BEFORE changing the verdict

| | unit (morning) | run (afternoon) |
|---|---|---|
| 5 battery fixtures | 3 fall · 2 pass | **identical** |
| 19 moulds | all < 1 | all < 1 (worst 0.85) |
| 12 test pages | 9 of 24 | **20 of 24** |
| 5 live sites | 3 FAIL · 2 PASS | **identical, and it finds one MORE block** |

Strictly better: fewer false, one more true, and zero laundered verdicts. The old measure is still published as
information — it stopped being the verdict, it did not stop being useful.

**The lesson:** the fix for a false accusation can bring its own. The only defence is measuring both rules
**over the same estate and before changing the verdict** — and accepting the new one only if it does not make a
single case worse. Had I changed the verdict in the morning and measured afterwards, I would have swapped eight
false ones for five false ones and called it a fix.

## §59 · Two of the five sites cannot be measured with a browser, and the gate was failing them

**Caught by:** the browser runner, which now publishes the page title, section count, whether there is a
`<main>` and a `suspicious` flag; and the door's browser step, which treats a suspicious run as **NOT MEASURED**
and not as FAIL.

Two sites serve the server's Chrome an anti-bot wall — *"Checking your browser before accessing. Just a
moment…"*, with its spinner — while `curl` receives the whole site: 23 KB, **10 sections, 15 calls to action.**

The gate was measuring the wall. It saw **1 screen and 0 calls to action**, and reported **FAIL · "only 0 CTAs
on the whole page."** A false accusation against **two of the five sites**, sustained for days.

### What made it invisible

**The width matched.** The house rule — *"innerWidth ALWAYS; if it does not match, it is rubbish"* — was
perfectly satisfied: the width was 390 because the wall also renders at 390. **A matching width says the width
is the one you asked for; it does not say what was measured is the page.** A correct check giving confidence
about something else.

And the asymmetry that gives it away: **the link crawler already had its "is this crawl valid?" rule**, and that
is why it said NOT VERIFIED on one of those sites. The browser gate did not have one. **Now it does.**

**The general shape:** every instrument needs a check that it measured **what it thinks it did**, not only that
it measured well. They are two different questions and the second does not answer the first.

> And what stays open: those two sites **still cannot be measured** for layout, density or contrast from the
> server. That is not a gate failure — it is a declared hole, and now it is declared instead of lying.
