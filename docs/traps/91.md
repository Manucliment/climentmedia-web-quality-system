## §91 · The "old in production" check read "more" as "worse", also where the number counts what is missing

When a browser gate fails on the candidate, `gates/d057.pl --navegador` asks whether the same
failure is already live. It compares each failure message with its numbers taken out, and then the
first number. The candidate's number must not be greater than production's: 5 offending elements
where production has 3 means 2 new ones.

That holds for almost every message, because they count what is too much: warnings, pixels, screens.
Two count what is **missing**:

- structure-gate's `ENLACES · N enlace(s) internos de CUERPO (minimo M …)`
- measure-screens' `solo N CTA en toda la pagina`

There a greater number is better. A page with 2 body links where production had 1 came out as
"1 of 1 NEW" and stopped the upload. The page had improved, but the minimum was 3, so it still
failed. The page was fixed by adding a third link, and the instrument stayed as it was.

**The other direction was worse, and nobody had seen it.** A page that went from 1 body link to 0
came out as old in production. With a row in the plan, it was uploaded.

**Why it was silent.** The bench had cases for "fixes part of it" (2 warnings where production has
3) but only for messages that count excess. Nothing tested a message where the scale points the
other way.

**The fix.** `@D57_FALTA` in `d057.pl` lists the message shapes that count what is missing, matched
against the number-free fingerprint. For those the comparison flips: the candidate must not be
*lower* than production. A new gate message that counts a minimum goes into that list, with its
case in the bench.

**The cheap signal.** The door calls a page NEW, and it has *more* of something than production does.

**Caught by:** `deploy-tests/tests.sh`, block D-057 in 1-quater. Five cases cover ENLACES and
«solo N CTA», in both directions and equal. Against the previous `d057.pl` four of them are red.
