# Traps §1–§19

Part 1 of 4. Index and families: [`../traps.md`](../traps.md).

Every one of these cost real time on a real migration. They are ordered by **how much they
cost**, not by when they happened. Each declares **what catches it now** — and `nobody` is a
valid, honest answer. The documentation gate fails if one of them does not declare it.

---

## §1 · The same field in TWO shapes — made twice

**Caught by:** nobody · it is a writing rule for the extractor: one field, ONE shape

A code formatter splits an array across several lines **only if it does not fit on one**. So
the same field appears both ways in the same file:

```ts
benefits: [                    |  benefits: ["We remove the pain", "Short sessions"],
  "Personalised diagnosis",    |
],                             |
```

**The error:** an opening rule that matches both shapes and then skips to the next line
**discards the single-line version with all its content inside.**

| Where | What was lost |
|---|---|
| Site D, `benefits` | **28 of 29** entries with no benefits |
| Site A, `postalCodes` | **4 of 5** cities with no postcodes |

**Neither raised an error.** The extractor finished, printed its record count, and delivered
less.

### The correct shape: resolve the inline form FIRST

```awk
# First the ONE-LINE version, which resolves completely and skips
/^    (postalCodes|neighbors|related): \[.*\],?[ ]*$/ {
  key=$0; sub(/^ +/,"",key); sub(/:.*/,"",key)
  s=$0; sub(/^[^[]*\[/,"",s)
  while (match(s,/"[^"]*"/)) { v=substr(s,RSTART+1,RLENGTH-2); s=substr(s,RSTART+RLENGTH); store(key,v) }
  next
}
# and ONLY THEN the multi-line opener
/^    postalCodes: \[/ { arr="pc"; next }
```

> **Rule:** if a field can arrive inline, that rule goes **first** and consumes the whole line.
> Never let the opening rule capture it.

## §2 · `grep -oc` does not count what you think

**Caught by:** nobody · writing rule: `grep -oc` counts lines, not occurrences

**The `-c` cancels the `-o`.** It returns the number of LINES with a match, not the number of
matches.

With one record per line that gives **1 per line**, and leads you to conclude data was lost
when the extraction was perfect.

```bash
grep -oc '{"q":' file.jsonl            # WRONG: returns 5  (lines)
grep -o  '{"q":' file.jsonl | wc -l    # RIGHT: returns 15 (matches)
```

**It happened like this:** I reported "bullets 18 → 6" and "faq 15 → 5" as data loss. Both
extractions were fine; the control was wrong.

> And its cousin: counting **all** the strings in an object JSON includes the **keys**.
> 57 localities + 5 region names = 62, and it looks like 5 too many.

## §3 · U+200B — the character you cannot see

**Caught by:** nobody · writing rule: normalise before comparing

Text pasted from documents carries a **zero-width space** at the start. It is only detectable
in hex:

```bash
printf '%s' "$text" | head -c 6 | od -An -tx1
#   e2 80 8b 4b 69 6e   <- e2 80 8b = U+200B
```

**The indirect clue:** a `sort` that puts a word starting with K *after* one starting with R.
Alphabetically impossible, so there is something in front of it.

**What it breaks, and why it is among the worst:**

- In a lead notification email, the service name arrives with invisible rubbish → any filter or
  automation matching exact text **fails silently**
- In a `<title>` or `<h1>` the page starts with a phantom character

**How to handle it:** the extractor copies it as is (an extractor does not fix things). The
cleaning goes in the generator and **is declared**, so it is visible that the site differs from
the source and why.

## §4 · `prefers-reduced-motion` without cancelling the DELAY

**Caught by:** nobody · writing rule: when cancelling an animation, cancel its delay too

The standard reduced-motion escape hatch usually cancels only the duration:

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.001ms !important;   /* NOT ENOUGH */
  }
}
```

With `animation-fill-mode: both`, **during the `animation-delay` the element stays on its first
frame, which is `opacity: 0`.** Result: headline, text, buttons and image **invisible** to
anybody who asked for less motion.

```css
    animation-delay: 0.001ms !important;      /* you need this too */
    transition-delay: 0.001ms !important;
```

**How it was found:** in a capture, the only visible thing in the hero was the eyebrow — the
only element **without a delay class**. Valid HTML, audit green, empty page.

> **The auditor tells you WHERE to look, not whether what is there makes sense.**

## §5 · Root-relative vs relative links

**Caught by:** nobody · partly covered by declaring the URL shape in the spec. **OPEN**

On a client site served from the root of its own domain, **root-relative (`/styles.css`) is
correct**: detail pages sit at depth 2 and hubs at 1, and with relative links you need a
different navigation per depth.

But our auditor **assumed relative links** and flagged **81 failures on a correct site.**

> *If the sweep says everything is broken at once, the broken thing is the sweep.*

Already corrected (it accepts both conventions). It is here because the correct reflex when
faced with 81 simultaneous failures is **to suspect the instrument.**

## §6 · Rules of ours that carry an assumption about US

**Caught by:** nobody · writing rule: a rule of ours cannot assume the site is ours

Our page standard forbids a particular schema type — and gives its reason: *"we are
service-area, not a shopfront."*

**That is true of us, not of the client.** A clinic with a door on the street needs it: it is
the schema its entire local search rests on.

> Before applying a rule from the standard to a client, read **its reason.** If the reason talks
> about us, the rule does not transfer on its own.

## §7 · Paths relative to the repo, not to the script's folder

**Caught by:** nobody · writing rule: the script locates itself (`cd "$(dirname ...)"`)

Pointers in a catalogue are usually written **from the repository root**. A script that changes
into its own folder and resolves from there marks **everything** as broken — including files
opened a minute ago.

Guard: check that the computed root contains a known file, and abort if it does not.

## §8 · `<p[^>]*>` also matches `<path>`

**Caught by:** nobody · hard rule: for HTML, a parser. Never a regular expression

Sites built with component libraries carry **inline SVG** icons. The pattern `<p[^>]*>` matches
`<path d="...">`: every icon opened a phantom paragraph that swallowed everything up to the
next `</p>`.

Symptom: a run-on string with half a section's text **concatenated without spaces**. It does
not error: it gives you a paragraph that looks like content.

```awk
# WRONG            # RIGHT — the tag name ends at ">" or at a space
"<" tag "[^>]*>"   "<" tag "( [^>]*)?>"
```

Affects `<b`/`<body`, `<i`/`<img`, `<a`/`<article`, `<s`/`<section` equally.

## §9 · Emission order: the card ends up with no text

**Caught by:** nobody · generator writing rule: the block ships whole or not at all

Emitting the paragraphs first (and marking them used) and the cards afterwards left every card
**without its description**, because its paragraph had already gone out loose.

On one page the result was **6 descriptions with no title followed by 5 cards with no
description.** And the extracted data had all 6 cards correct: **the data was intact, what was
wrong was the order.**

→ **Compute the cards FIRST** (reserving title + text as used) and **print them afterwards.**
Whatever paragraphs are left over are real paragraphs.

Corollary: **a grid of cards does not have a heading of its own.** Promoting the first heading
to a section title ate one service out of six. Rule: if there are ≥3 sibling headings at the
same level and no top-level heading, they are all cards.

## §10 · `for (i in arr)` in awk iterates in UNDEFINED order

**Caught by:** nobody · writing rule: in awk, iterate by index, never `for (i in arr)`

Walking a split array with `for (i in arr)` **does not respect order**. With few elements it
usually looks as though it does, which is why it goes unnoticed until a page ships with its
paragraphs shuffled.

```awk
n = split(s, arr, SUBSEP)
for (i = 1; i <= n; i++) { ... }   # and not: for (i in arr)
```

## §11 · `grep -P` with `{0,N}` counts BYTES, not characters

**Caught by:** nobody · writing rule: count characters, not bytes

Brother of §2, and from the same family: **the broken instrument, not the broken system.**

`grep -oP '"t":"[^"]{0,40}"'` over accented text does not find the long titles: accented
characters take **two bytes**, so a 38-character title exceeds 40. Apparent conclusion: *"the
extractor only pulled one card."* Reality: there were five.

→ Before believing in data loss, **count over the generated file**
(`grep -o '<article class="card">' out.html | wc -l`), which does not depend on the regex.

## §12 · The published site LIES by omission

**Caught by:** `audit-vs-source.sh` — it enumerates from THEIR code, not from their site

The most expensive thing in the second migration.

| What gets lost | Why |
|---|---|
| FAQ answers | The accordion **only renders the open one**; the folded ones are not in the DOM |
| A whole FAQ | There may be no structured data for it on that particular page |
| The forms | They are painted client-side: with `curl`, the page **has no `<form>`** |
| That a form is broken | A `mailto:` redirect does not show in the render |
| The correct label | Two vocabularies in their repo, and the render does not say which one each place uses |
| Content their template does not paint | Their data files may have rich content their site never shows |

That last case deserves attention: on one migration, the **5 city pages were exact clones** of
their hub (the only difference was the `<title>`), while their data file had, per city, an
intro, localities, 5–22 postcodes and 3 FAQs. **Publishing what they had already written is not
touching their copy**; it goes in `overrides` with the evidence.

> And it travels **with** the canonical fix: correcting the canonical without giving each page
> its own content is telling the search engine to index N duplicates.

## §14 · The auditor carried an assumption about URL SHAPE

**Caught by:** nobody · same hole as §5: the URL shape has to be declared. **OPEN**

**Changing the site from `/page/` to `/page` put its own gate at 78 failures.** The site was
correct: what was wrong was the auditor.

Two checks assumed, without declaring it, that a directory index is indexed **with** a slash:

- The "indexable but outside the sitemap" check compared the slashed form against a sitemap that
  now says the unslashed one → **40 false "outside the sitemap"**.
- The orphan check only resolved the slashed form to its index file, so a link to the unslashed
  path stayed a directory and **nobody counted its inbound link**: 40 orphans on a
  well-linked site.

Fix: **accept both conventions**, in both places.

This is the third time this family appears in the same repository. The pattern:

> **A verification tool with an undeclared assumption does not fail: it accuses.** And because
> it accuses in bulk, it looks like a disaster in the site.
>
> *If the sweep says everything is broken at once, the broken thing is the sweep.*

> **Practical corollary:** when you change a site convention (URL shape, folder structure, class
> names), **review the gates BEFORE believing their verdict** — and fix the gate, not the site.

## §15 · Half-applied cache-busting is WORSE than none

**Caught by:** nobody · writing rule: cache-busting is all or nothing

**ES modules are cached by URL, not by resolved path.** `./site.js` and `./site.js?v=20260803`
are **two different modules**: the browser executes both, and each has its own copy of whatever
the module declares at top level. If that module holds state — a cart, a store, a singleton —
you end up with **two parallel states that do not talk to each other.**

**It happened on a live shop.** One `.js` was uploaded raw to a site where every other file
carries a version query injected at deploy time. One page went from loading 6 modules to
loading **11**, with two instances of the core script and two of the cart. "Add to cart" wrote
into a cart the header was not listening to, and opening the cart threw. **Zero console errors.
The page loaded perfectly.**

**Why nothing routine catches it:** the failure is one of *module identity*, not syntax or
network. The uploaded file is fine — a syntax check passes, the `.js` returns 200, the md5
against local matches. What is wrong is **who it shares state with.** Every per-file check
passes and the set is broken.

→ **Before uploading a `.js` to a site with sealing, read the seal from the equivalent LIVE file
  and use THE SAME ONE.** It goes in every stylesheet link, every module script **and every
  internal `import` inside the `.js` itself** — that last one is the one people forget.
→ **Post-deploy check, in the page** (not on the server):
  ```js
  performance.getEntriesByType('resource')
    .filter(r => r.name.includes('/js/') && !r.name.includes('?v='))
  ```
  It must return `[]`. And **the total module count must be the same as before the change**: if
  it went up, you have duplicates.
→ **If the sealing is removed, it is removed from ALL of them at once.** Never from one.
→ It generalises to any URL-based invalidation. The question is not *"is this file right?"* but
  **"do they all still agree?"**

**And the root cause of it happening at all: the step was not written down anywhere.** A manual
deploy step that lives only in the head of whoever deployed last is a step that will be skipped.
**If a project seals and does not automate it, the step goes in that project's notes or it does
not exist.**

## §16 · Two programs, one cache, and not a single error

**Caught by:** the crawler's test battery (cache collision) and the master gate's

The master gate and the link crawler cached **with the same key — `md5(url)` — in the same
directory**, and the QA document told both to use the same path. But their metadata files are
not the same format:

| | separator | fields | writes headers |
|---|---|---|---|
| master gate | tab | 5 | yes |
| link crawler | pipe | 4 | **no** |

Whichever read the other's file got a split that returns **one single field.**

**What was written in the code was false, and that is the lesson.** It said "the whole line is
read as the status code, it is not a number, and the page is discarded." Measured: **it does
numify** — Perl gets `200` out of `"200|https://…|0|text/html"`, so the page passed **every**
`code == 200` check without noticing. What was lost was the rest: transfer size, content type
and effective URL all undefined, and the header file non-existent.

**The proof, on a live site** (same binary, same site, the only variable is the cache):

```
clean cache        compression check PASSES  html=br js=br css=br
crawler's cache    compression check FAILS   "text served UNCOMPRESSED"
```

A **false red that blocks a legitimate deploy**, on a site that serves brotli: with no header
file there is no content-encoding to read. In other checks the sign inverts — with transfer
size 0, everything filtering on `size > 0` silently skips. **What they have in common is not
the colour: it is that the number comes from a page that program never downloaded.**

→ **The fix is to VALIDATE ON READ, in both**: if the metadata does not have the shape *this*
  program writes, it is not a cache hit, it is a miss, and it re-downloads. About 7 lines each.
→ **Do NOT change the key.** Adding a prefix namespaces properly, but invalidates the
  pre-populated fixture caches: it took the battery from 180 to 170. Tried and reverted.
→ **And the failure was symmetric:** the crawler reading the gate's metadata ends up with an
  empty content type and **zero redirects on every page** — the graph would say nothing
  redirects anywhere.

### The part that explains why nobody saw it for three months

**The root does not collide.** The crawler caches the home with a trailing slash and the gate
normalises **without** it: two different keys. What collides are the **subpages**. Measuring a
single page, both runs come out identical and it looks like nothing is wrong — the difference
only appears measuring the whole site.

> It generalises: **two writers in a shared namespace do not fail, they diverge.** If two tools
> share a hash-indexed directory, each has to recognise its own. Separating the paths is a
> saving, **not the guarantee.**

## §17 · A positive control anchored to a LIVE site expires the day you fix the site

**Caught by:** a frozen, network-free fixture directory — the positive control

The master gate's battery reported **`OK 180 · FAIL 0`**. With a fresh cache, **`OK 172 · FAIL
10`**. All 10 were from one site and all said the same thing: *expected FAIL, got PASS.*

The gate was not broken: **the site had been deployed and those defects no longer existed.** The
warm cache held the old bytes:

| | in the cache | live |
|---|---|---|
| the primary colour token | `oklch(0.58 …)` | `oklch(0.54 …)` |
| the favicon | 320,221 B | 3,280 B |
| a portrait | 2,338,296 B | 49,826 B |

The number the hard rule declares untouchable **was not reproducible from scratch.** The day
somebody cleared the temp directory it would have dropped to 172, and the natural reading is
"I broke the gate" — with two bad exits: re-point the expectation (switching the case off
without saying so) or lose an afternoon.

**The cause is not those 10 lines, it is the design.** A battery that tests the gate against
production measures two things at once and cannot tell them apart: when a case changes colour
you do not know whether the gate moved or the site moved. **Fixing the site breaks the test.**

→ **The evidence gets frozen.** Done: a fixture directory holds the 94 cache triples the battery
  was reading, and the 19 invocations point there.
→ **And the fixture needs its own gate.** An incomplete one **raises no error**: the gate goes
  out to the network for whatever is missing and half the measurement is production again
  without anybody noticing. Count the cache files before and after: if a new one appears, there
  was a download → FAIL with the list of URLs.
→ **Never re-point the expectation.** If a positive case stops failing because the site got
  fixed, you freeze it or you retire it; changing its expected colour is switching it off
  without writing it down.
→ **Run the battery cold from time to time**, or you do not know what it is measuring.

## §18 · A whole lens NOT VERIFIED and the verdict said `PASS`

**Caught by:** the receipt coverage battery ("a lens that ran and measured nothing"): 5 cases

With the home page unreachable, running one lens correctly emits `[NOT VERIF] the whole lens` —
and then printed **`VERDICT: PASS`**, because there is no FAIL to count.

Measured, it came out **worse than it had been written down**:

```
[NOT VERIF] SEO-00    the whole lens
VERDICT: PASS
  FAIL 0 · WARN 0 · ACCEPTED 0 · NOT VERIFIED 1 · PASS 0      <- zero measured
exit 0
.qa-receipt:  LENS-SEO: PASS                                  <- sealed as approved!
```

**Zero checks passed, and both faces — verdict and receipt — saying yes.** The seal came from a
two-branch ternary: `(grep FAIL) ? 'FAIL' : 'PASS'` — with no third state, "I measured nothing"
falls on the good side. And the receipt validator accepts **any** lens that says PASS or FAIL,
so the door swallowed it as a pass.

> In the reproduced case the door stopped it anyway, but **for a different reason** (the other
> four lenses had not run). The dangerous case is the one never tested: **all five lenses run and
> one of them measuring nothing.** There, nothing would have stopped it.

**Fixed in the two places that computed the same thing twice:**

- Three states per lens, not two: `FAIL` · `PASS` · **`NOT VERIFIED`**, meaning "it ran and
  **all** its checks came back NOT VERIFIED." A single PASS or a single WARN already means it
  looked at something.
- The verdict carries it: `VERDICT: PASS · 1 lens NOT MEASURED: SEO`. Same reason as the
  accepted-count suffix — somebody reading a bare "PASS" has not seen the report.
- The door distinguishes **two different holes**: `NOT RUN` (never launched) and `NOT VERIFIED`
  (ran, measured nothing). Telling somebody who did run it that they did not sends them to fix
  the wrong thing, and that costs an afternoon.

> **On method, and it nearly slipped through:** the first test case used the battery's own "dead"
> port, which **stops being dead further down the same file**, where that battery starts a server
> on it. The case came out FAIL instead of NOT VERIFIED — the lens really was measuring, because
> something was answering. **A name is not a guarantee:** the case now checks with `curl` that
> nobody answers **before** measuring, and that check is one of the five.

## §19 · Measuring a site OVERWRITES its deploy receipt

**Caught by:** the master gate's `--no-receipt` flag, and the receipt validator, which rejects a
receipt with lenses that did not run

`qa-master.pl --repo DIR` **writes `DIR/.qa-receipt`** unless you pass `--no-receipt`. It does
not distinguish between "I am preparing a deploy" and "I am looking at something": the receipt
is a side effect of measuring.

**Five sites lost their receipt in 55 seconds.** The timestamps tell it on their own —
`16:17:53`, `16:18:05`, `16:18:18`, `16:18:38`, `16:18:48` — and all five ended up
`MEASURED-AGAINST: PRODUCTION · VERDICT: FAIL`. A diagnostic sweep deleted the work of preparing
five deploys.

**Why it hurts more than it looks:** a production receipt is not a useless receipt, it is one
that **answers a different question.** It says how what is ALREADY uploaded is doing; the deploy
needs to know how **the tree you are about to upload** is doing. The door accepts it with a
loud warning, and that warning is easy to skim past when the verdict is already green.

→ **To look, use `--no-receipt`.** Always. The receipt gets written when you are preparing an
  upload, not when you are investigating.
→ **Before deploying, read the receipt's header**, not just the verdict: what it was measured
  against, when, and its scope. A receipt from ten minutes ago can be talking about something
  else.
→ It generalises: **a decision artefact cannot be the side effect of a diagnostic tool.** If
  looking and deciding write to the same place, looking ends up deleting decisions.
