## §88 · A download cache committed next to the BEFORE file measured the site as it was seven weeks earlier

`paths/2-improve-site.md` ran the BEFORE measurement with `--cache "$REPO/_qa/cache"`. That is right
next to the JSON, which is meant to live in the repository. On one site the cache was committed
along with the JSON: 180 responses, on 19-aug. `qa-master.pl` reused any download of its own it
found in `--cache`, however old it was.

On 7-oct a "production" measurement with that cache reported four FAILs at once:

- EST-09 «28 of 28 files differ»;
- a single og:image for the whole site;
- duplicated descriptions;
- an incomplete anatomy on 8 pages.

All four described the site of 19-aug. Production was serving the repository byte for byte. The
md5 of five served pages matched the repository, and the last `SERVIDO` line of the history matched
the base's tree hash. A second site's repository had the same directory committed: 120 responses.

**Why it was silent.** The header still said «MEDIDO PRODUCCION · … (lo que ve el visitante hoy)».
Nothing in the output told a page downloaded now from one downloaded seven weeks earlier. A
file-date check would not have caught it either. Whatever comes out of git, a `cp` or a `tar`
carries today's date, so the seven-week-old cache would have looked fresh. `crawl-links.pl` has
expired its own cache by file date since 18-aug, and for a committed cache that defence does not
fire.

**The fix.**

- Every download now leaves a `.when` file holding its own date, written by the program that
  downloaded it.
- A download is reused only if it comes from the same run, or if its date is younger than
  `--cache-hours N` (default 0). An undated download is never reused: that is exactly what a
  committed cache, or one made before this fix, looks like.
- Anything reused is printed on a `CACHE` line in the header and recorded in `instrumento.cache` in
  the JSON, and the `MEDIDO` line stops saying "today".
- `qa-diff.pl` says so at the top when either side reused downloads.
- `receipt.pl --served --cache` (G11) had the same defect in `baja()`. It now follows the same rule
  and adds a line saying the reused files are not what is served now.
- The improve-site path no longer puts the cache in the repository.

**Why the default is 0 and not the receipt's 12 hours.** Improving a site normally means measure,
deploy, measure again, and often all within the hour. With the same `--cache` and a 12-hour window,
the AFTER would be the BEFORE. `qa-diff.pl` would then report «NADA HA CAMBIADO» about a deploy that
did change things.

**The cheap signal.** Several FAILs at once on something nobody touched. Before believing a
production measurement, compare the md5 of one served page with the repository's copy. It takes one
second.

**Caught by:**

- `qa-master-tests/tests.sh`, block «LA CACHE NO MIDE EL PASADO». An undated download is downloaded
  again, with or without `--cache-hours`. By default, so is a download from a previous run. With
  `--cache-hours 1`, a 1-minute-old download is read and the reuse is declared; a 30-day-old one
  is not read. Every download leaves its `.when`. A non-numeric `--cache-hours` stops the run.
  `qa-diff.pl` warns when one side reused downloads and stays silent when neither did.
- `receipt-tests/tests-coverage.sh`, section 8. G11 runs with an aged copy of the homepage in the
  cache. Undated, and by default, it downloads the page again. With `--cache-hours` it reuses the
  copy, and says that copy is not what is served now.

**Seen failing against the previous code first:**

- The block's first ten cases: 9 of them fail, and so does the collision block's «the page was read
  from it».
- Section 8: six of its seven checks fail. The seventh is an exit 2 for a non-numeric value, which
  the old program also gives for an unknown option. The message check next to it fails there.
- The `qa-diff.pl` warning: none with the old `qa-diff.pl`, on the same JSON.

What passes on the old code passes for a reason that was checked. Two `AUSENTE` results are also
what the old program prints when it dies on the unknown option, and each sits next to a "the page
was read" check that fails there. The negative controls ("stays silent", "the control diff ran")
pass on both versions, which is their job.
