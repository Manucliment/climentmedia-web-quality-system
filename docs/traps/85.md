## §85 · Three checks written for sites that collect leads failed two sites that collect nothing

Two small static sites were built on the same day with the greenfield path: a personal page for
the person behind a business, and a page explaining where a retired brand went. Neither has a
form, a script, an iframe or any measurement; both link their privacy notice from the footer and
their contact is a `mailto:` link.

The gates came back with **three FAILs between them, and none was a defect of either site**:

| Check | What it demanded | Why it did not apply |
|---|---|---|
| `INT-01` (spec auditor) | a phone, opening hours and areas served | a personal page has no opening hours and no service area, and a personal phone is not published. Only the address had a way to say "we do not publish it" (`noAddress`) |
| `MED-02` (spec auditor) | a thank-you page, `noindex`, with a conversion marker | with no form there is nothing to say thank you after |
| `EST-12b` (master gate) | **≥2** legal links in the footer | its own reason is *"a site that collects data and hides its policy"*. These collect nothing and link the one policy they need |

**Why it matters more than three red lines.** The only ways to turn them green were to write a
false value into the spec, to add a thank-you page nobody can reach, or to invent a second legal
page — that is, to change a truth for a green. And the master gate's FAIL **blocks the door**, so
the pressure to do exactly that lands on the person trying to publish.

**The fix, one per check, each conservative on purpose:**

- `INT-01` accepts `nap.noTelephone`, `nap.noHours` and `nap.noAreaServed` with the same rule as
  `noAddress`: a written reason counts, a bare `true` does not. The PASS line names every
  declaration it accepted, so a decision never reads as a fact.
- `MED-02` does not demand a thank-you page when **no page** carries a `<form>`, an executable
  `<script>` or an `<iframe>`, and the spec declares no container.
- `EST-12b` asks for **1** legal link instead of 2 under the same condition, and says so in a PASS
  line with the measured reason. **One signal on one page brings back the old threshold.** A
  script is enough on purpose: a measurement id can live inside a `.js` the HTML only loads, and a
  third-party form arrives through a script or an iframe without a single `<form>` in the page.

**Seen red first.** Against the old spec auditor the new battery gave **75 OK · 2 MAL** — exactly
the two new green cases — and **77 OK** against the new one. The new master-gate fixture gave FAIL
before and PASS after. And the three red controls stay red on both: no legal link at all, a
`<script>` with one legal link, and the existing one-legal-link fixture — which had to be given
the `<form>` its own comment claimed it had, or it would have turned green for the wrong reason.

**Caught by:** `audit-vs-spec-tests/tests.pl` (INT-01 ×2, MED-02 ×3) and
`qa-master-tests/tests.sh` (EST-12b ×3), each with its red controls.

**The cheap signal:** a FAIL whose `hacer` line describes a situation the site is not in. Read the
reason written next to the check before obeying its threshold.

### Same day, second round: the house's own measurement pattern was invisible

The owner then asked for both sites to measure, like the agency's own site does: a first-party
`consent.js` that loads nothing until the visitor accepts, and only then injects the tag manager.
The pages never carry the container ID; the script they all load does. The spec auditor could not
see that shape, three ways:

| Check | What it said | Why |
|---|---|---|
| `MED-01` | NOT VERIFIED, *"no runtime JS found"*, with the runtime right there | it looked for the runtime under three fixed names (`script.js`, `assets/script.js`, `js/site.js`) |
| `MED-03` | would FAIL every page once the spec declared the container | it looked for the ID in the HTML only |
| `MED-02` | FAIL, *"no thank-you page"* | the consent script is a `<script>`, so the first round's exemption no longer applied — and a site whose only conversion is a click on a mailto has no submission to thank anyone after |

**The fix:** the pages' own scripts count. A `<script src>` with no scheme and no `//` in front,
stripped of its `?v=` and present in the tree, is part of the runtime for `MED-01` and a place
the container can live for `MED-03`, whose PASS line says which way it found it. An external
script is never read: it is not ours. And `MED-02` accepts `contact.noForm` **with a written
reason**, under the same rule as `nap.noAddress` — a bare `true` or `si` does not count, and a
`<form>` or an `<iframe>` on any page contradicts the declaration and brings the FAIL back.

**Seen red first.** The 12 new cases against the old auditor: **89 OK · 4 MAL** — the three new
green cases, plus the red control *"an own script that does not read the attribute"*, which the old
auditor could only call NOT VERIFIED because it never found the script. **93 OK** against the new one.
The red controls that guard against over-permissiveness stay red on both: a page that does not load
the script, a script without the ID, an external script, a bare `true`, a bare `si`, a `<form>`, an
`<iframe>`.

**Caught by:** `audit-vs-spec-tests/tests.pl` (MED-01 ×3, MED-02 ×5, MED-03 ×4).

**Still blind, on purpose for now:** `qa-master.pl`'s measurement lens looks for the container in the
served HTML, so on these sites it still says `MED-01` *"no measurement at all"* — the same false line
the agency's site has carried since 2-sep-2026, documented there. Its consent-order check (`MED-02`
there) never runs on them for the same reason. Verify the consent flow in a browser until that lens
learns to read first-party scripts too.
